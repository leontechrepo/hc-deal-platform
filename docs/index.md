# HC Deal Platform — Documentation

Internal deal pipeline management tool for Corporate Credit. Tracks healthcare deals, monitors inboxes for relevant emails via Microsoft Graph, and uses Claude AI to propose deal updates for human review.

- [App Guide](app-guide.md) — stack, local development, project structure, deployment
- [API Reference](api-reference.md) — the FastAPI routers mounted under `app/api/`
- [Intake pipeline rollout](intake-rollout.md) — the Microsoft Graph delta-sync mail scanner, attachment ingestion, document extraction, migrations, feature flags, and rollout/rollback steps for the intake v2 pipeline

## Recent changes

- **2026-10-02 — Intake v2: delta-sync scanner, attachment ingestion, extraction review, leon-ui Inbox.** The largest change to date: Microsoft Graph mail sync moved to per-mailbox/folder **delta** sync with page checkpoints, 410 resync, and folder parking after repeated failures; scanning is now crash-safe (advisory lock on a dedicated connection, per-message claims, stale-claim recovery, cross-mailbox dedupe) with full cost/token accounting in `llm_calls`; worthwhile email attachments can be stored as **unfiled** documents behind `ATTACHMENT_INGESTION_ENABLED`; and an opt-in, reviewable **document extraction** workflow (behind `DOCUMENT_EXTRACTION_ENABLED`, needs ingestion) proposes Corporate Credit field values from uploaded documents with evidence, confidence, and a disposition, never overwriting a populated field without an explicit reviewer override. Five new migrations (`036`–`040`). The frontend migrated to the `@leontechrepo/leon-ui` shell/theme and the Inbox moved to group-level review (one editable form per email, a single confidence badge, collapsible review/attachments, live email body). New routers: `admin.py` (scan-run/cost/sync-state visibility and unparking), `meta.py` (`GET /api/meta/features` effective-flag reporting), `extractions.py` (extraction runs and candidate accept/reject). See [Intake pipeline rollout](intake-rollout.md) for the full rollout sequence, feature flags, and rollback steps, and [API Reference](api-reference.md) for the new/changed endpoints.
- **2026-10-02 — Deploy fixes: Docker multi-stage build and `.gitignore` anchoring.** The frontend's production image now builds in a separate Node stage that takes `LEON_UI_TOKEN` as a build `ARG` and copies only `frontend/dist` into the Python image, so the npm auth token used to install the private `@leontechrepo/leon-ui` package never ships in the final image's layers (plus a `.dockerignore` keeping local `node_modules`/env files out of the build context) — fixing an `E401` from the token not being available/copied before `npm install`, and an npm auth failure from Railway rejecting BuildKit secret mounts (only cache mounts are allowed there). Separately, `frontend/.gitignore`'s bare `logs` pattern was matching `src/components/logs/`, so `SyncStatusCard` was never committed and the production build failed with `TS2307`; the rule is now anchored to `/logs` and the missing files were added.
- **2026-09-22 ([#24](https://github.com/leontechrepo/hc-deal-platform/pull/24)) — Aikido dependency security update.** Bumped `frontend/package.json` / `frontend/package-lock.json`: `react-router-dom` `^7.16.0` → `^7.18.2` (and its `react-router` peer to `7.18.4`), `recharts` `^3.8.1` → `^3.9.1` (pulling in `immer` 10.2.0 → 11.1.18 and `reselect` 5.1.1 → 5.2.0), `@clerk/shared` 4.14.0 → 4.33.0, and `js-cookie` 3.0.7 → 3.0.8, among other transitive lockfile updates. No application code changed — dependency versions only.
